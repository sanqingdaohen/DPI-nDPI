## 一、这份文档到底是干什么的？（用大白话）

### 1.1 先懂"信道"是什么

Wi-Fi 不是一条"路"，而是分了很多条"车道"——这些车道叫**信道（channel）**。

- 2.4GHz 频段有 1~13 信道（常用 1/6/11）
- 5GHz 频段有 36/40/44/48/149/153… 等更多信道

你家的路由器占一条车道，邻居家的路由器也占一条车道。**如果大家挤在同一条/相邻的车道上，就会互相干扰**，表现为：网速变慢、视频卡顿、延迟变高。

### 1.2 ACS 是什么

**ACS = Automatic Channel Selection = 自动信道选择**。

就是路由器自己：
1. **盯着当前车道**——是不是变堵了？（健康度评分）
2. 堵了就**看看别的车道**——哪些更空、更快、更稳？（扫描 + 候选评分）
3. 挑一个**更好的车道换过去**——但**换的时机要挑"没人用网的时候"**，不能在你正看视频/打游戏时切（安全窗口）

一句话：**ACS = 路由器版的"智能车道选择器"，核心原则是"能不换就不换，要换就趁没人用网时换"。**

### 1.3 文档的工程定位

这不是概念介绍，而是一份**可以直接照着写代码、写测试、调参数**的落地设计：
- 有系统主流程图（mermaid）
- 有数据结构定义（C 语言 struct）
- 有接口签名（函数原型）
- 有**关键 C 代码实现**（CSV 解析、评分、决策、在线学习）
- 有参数表（所有阈值默认值）
- 有测试用例和现场 KPI

## 三、核心机制逐个解释（每个都配例子）

### 3.1 环境识别（先看"你家网络是什么病"，再决定"怎么治"）

- **是什么**：路由器先给整个网络环境"分个类"，分成 5 种：
  `ENV_BALANCED`（均衡）/ `ENV_INTERFERENCE_HEAVY`（干扰严重）/ `ENV_WEAK_COVERAGE`（信号弱）/ `ENV_BACKHAUL_CONSTRAINED`（回程受限）/ `ENV_DFS_SENSITIVE`（DFS 敏感）
- **为什么先识别环境**：不同"病"要下不同"药"——干扰严重的环境，评分时把"干扰"权重调高；信号弱的环境，把"速率/覆盖"权重调高。
- **例子**：你家小区公寓楼，周围 20 个邻居 WiFi → 识别为"干扰严重环境" → 评分时 `w_cci`（同信道干扰权重）加大 → 选信道时优先躲开邻居用的信道。

### 3.2 两阶段评分（先"守门"，再"选优"）

这是全文最重要的设计，分两个阶段：

**阶段 1：当前信道健康评分（HealthScore，守门）**
- 只看当前信道，算一个 0~100 的分。
- 分数 ≥ 65：信道还行，**啥也不干**，继续监控。
- 分数 < 65 且连续 3 次：信道确实坏了，才进入下一步（防抖）。
- 分数 < 20：**强制切换**（信道已经烂透了，不管什么业务都要换）。

**阶段 2：候选信道决策评分（DecisionScore，选优）**
- 把候选信道挨个打分，分高的胜出。
- 但**必须比当前信道高出一个阈值**（如 8~14 分）才换——避免"换来换去没意义"。

> 关键设计：**绝大多数周期只做阶段 1（几乎零开销），只有信道真坏了才做阶段 2（全信道扫描）**——这就是文档强调的"默认不做全信道评分，只监控当前信道健康度"。

### 3.3 业务感知（6 类业务，不同待遇）

路由器的流分类模块（`flow classify`）把流量识别成 **6 类业务（BIZ）**：

| BIZ | 含义 | 例子的待遇 |
|---|---|---|
| `IDLE` | 空闲 | 随便切，阈值最低（8 分就切） |
| `WEB` | 网页 | 可切，阈值 10 |
| `VIDEO` | 视频 | **谨慎切**（切了会卡顿），阈值 14，且只在安全窗口切 |
| `CALL` | 语音通话 | **禁止主动切**（一切就断线） |
| `GAME` | 游戏 | **禁止主动切**（一切就掉线/高延迟） |
| `BULK` | 大流量下载 | 可切，阈值 12 |

> 例子：晚上 8 点你在打游戏（GAME），路由器就算发现信道变差了，**也忍着不切**——因为一切换你游戏就卡一下。它只会继续监控，等游戏结束（变成 IDLE/WEB）再考虑。

### 3.4 自学习（记住"什么时候忙、什么时候闲"）—— 你们专利的最相关部分

这是全文档里**最像"用户画像 + 时空规则 + few-shot"**的部分：

- **时隙（slot）**：一天切成 **96 个 15 分钟窗口**（24h × 4）。
- **CSV 历史学习**：`flow classify` 持续把流量统计写进 `test.csv`，ACS 把每条记录按时间戳归到某个时隙，统计"这个时隙里 6 类业务各占多少比例"——形成 `slot_prob[96][6]` 概率表（**这就是"按时间维度的用户行为画像"**）。
- **EWMA 在线更新**：每来一条新记录，用指数加权平均更新概率（λ=0.85），**新数据影响大、旧数据慢慢遗忘**——这样用户作息变了（比如搬家后改晚上 10 点才看视频），模型能跟上。
- **JSD 漂移检测**：比较"短期规律"和"长期规律"差异有多大（Jensen-Shannon 散度），差得太多说明用户行为变了（漂移），就**临时提高短期数据权重**，快速适应新作息。
- **输出**：预测"下一个时隙忙不忙"→ 忙的时隙不扫描不切换，闲的时隙主动优化。

> **和你们专利的对应关系**：
> - "96 时隙 × 6 业务概率" = **基于时间的用户画像**
> - "CSV 导入 + EWMA" = **少量历史样本即可学习（few-shot 思想的工程版）**
> - "不同时隙不同策略" = **时空规则**
> 这份文档就是"时空规则画像 + 少量样本自适应"的**现成实现蓝本**，写专利时可以直接引用其机制（但要用你们自己的措辞和创新点包装）。

### 3.5 主动 vs 被动两条优化路径

| 路径 | 触发条件 | 例子 |
|---|---|---|
| **被动路径** | 当前信道健康分连续 3 次 < 65 | 信道被邻居干扰搞坏了 → 被动去救 |
| **主动路径** | 自学习预测到"空闲时段到了"（且距上次主动扫描 ≥ 24h） | 每天凌晨 3 点没人用网 → 主动全信道扫一遍，看有没有更优信道 |

> 两条路径共用同一条"扫描→评分→决策→切换"流水线，只是**触发来源不同、阈值不同**（主动更保守：阈值 12~18；被动更急：8~14）。

### 3.6 安全窗口（切换前最后一道闸）

就算候选信道赢了，还要确认**现在适不适合切**：
- 无实时业务（没人在视频/通话/游戏）
- 发送队列空闲（txq < 20%）
- CPU/内存不紧张

> 例子：候选信道比当前好 15 分，但你现在正在看视频 → 不切，进入"等待安全窗口"状态。等视频放完、队列空了再切。**被动入口等 5 分钟超时后可降级切**（实在没法等），主动入口等 2 小时超时直接放弃（不值得等）。

### 3.7 DFS 雷达避让（法规红线）

- **DFS 信道**：5GHz 有一部分信道是雷达共用的（气象/军事雷达），法规要求路由器在这些信道上**必须能检测到雷达并立刻让开**。
- **CAC**：切换到一个 DFS 信道前，要**先监听 60 秒**确认没有雷达（Channel Availability Check）。
- **NOP**：一旦检测到雷达，该信道 **30 分钟**内不能再使用（Non-Occupancy Period）。
- **应急流程**：收到雷达事件 → 当前信道拉黑 → 立刻切到备用信道（优先非 DFS 信道）→ 进冷却。

> 例子：路由器在信道 100（DFS 信道）上工作，突然检测到雷达信号 → 3 秒内切到信道 149（非 DFS）→ 信道 100 进 NOP，30 分钟内不再用。

### 3.8 Mesh 多 AP 协同（全家路由器一起选）

- **Mesh**：一台主路由 + 几台子路由（节点），共享一个 Wi-Fi 名字，全屋无缝漫游。
- **问题**：各节点如果各选各的信道，可能互相干扰（子路由的回程和覆盖打架）。
- **方案**：控制器把所有节点的候选信道**穷举组合**（N≤4 个节点 × 每个保留 4 个候选 → ≤256 种组合），选一个**全网总分最高**的组合；切换顺序：先叶子 → 再中继 → 最后主节点。

### 3.9 防抖机制（防止路由器"神经质"地来回切）

四个保险，层层设防：
1. **连续劣化 3 次**才触发扫描（瞬时抖动不算）
2. **连续获胜 N 次**才切换（一次领先不算，要稳定领先，N 按环境 3~5 次）
3. **最短驻留 30 分钟**（刚切过来，至少待 30 分钟）
4. **冷却 1 小时**（切完 1 小时内不许再切）

> 例子：候选信道 38 分、当前 30 分，领先 8 分刚好达到阈值 → 但只领先 1 次 → 不切。连续 3 次评估都领先 ≥8 分 → 才切。切完进入 1 小时冷却。

## 四、一个完整例子：把整个流程走一遍

**场景**：周六晚上 20:15，你家客厅电视在播 Netflix 4K（VIDEO），你在卧室打游戏（GAME），路由器 5G 当前在信道 36。

```
20:00  路由器周期监控：读当前信道 36 的指标
       → 发现：邻居新装了个路由器也在信道 36，忙时比 70%（超标）
       → HealthScore = 55（< 65）→ 劣化计数 +1
20:05  第二次评估：仍差 → 劣化计数 +2
20:10  第三次评估：仍差 → 劣化计数 = 3 → 触发"需要扫描"

       → 读 test.csv：当前 20:15 时隙，历史统计显示 80% 概率是 VIDEO/GAME
       → BIZ 判定 = VIDEO（电视流量占比大）
       → 业务策略查表：VIDEO 只允许在"安全窗口"扫描
       → 检查安全窗口：txq 队列忙（>20%）→ 不满足 → 【先不扫】

21:30  电视关了，游戏停了（业务变 IDLE）
       → 安全窗口满足 → 触发全信道扫描
       → 扫描结果：信道 149 忙时比 20%，噪声更低，RSSI 更好
       → 候选 149 的 DecisionScore = 82，当前 36 的 DecisionScore = 60
       → 收益 = 22 > 阈值 8（IDLE 被动阈值）✓
       → 连续获胜：第 1 次 ✓（需 3 次）

21:35  再评估一次：149 仍领先 → 第 2 次 ✓
21:40  再评估：149 仍领先 → 第 3 次 ✓ → 驻留时间 ≥30min ✓ → 冷却已过 ✓
       → DFS 检查：149 是非 DFS 信道，不需要 CAC ✓
       → 发送 CSA 通告 → 切换到信道 149
       → 进入 1 小时冷却，更新状态

02:00  （第二天凌晨）主动路径触发：自学习预测"02:00 时隙空闲"
       → 主动全信道扫描，找有没有比 149 更好的
       → 没找到明显更优 → 保持 149，放弃本轮
```

**结果**：整个晚上视频没卡、游戏没掉线，路由器悄悄在没人用网时把信道从拥挤的 36 换到了空旷的 149。

## 五、专业术语速查表（中英对照 + 大白话 + 例子）

| 术语 | 全称/英文 | 大白话 | 例子 |
|---|---|---|---|
| **ACS** | Automatic Channel Selection | 自动信道选择 | 路由器自己挑一条最好的 Wi-Fi 车道 |
| **AP** | Access Point | 接入点（路由器） | 你家那台路由器 |
| **Mesh** | — | 多台路由器组网，一个 Wi-Fi 名全覆盖 | 主路由 + 客厅/卧室子路由 |
| **信道** | Channel | Wi-Fi 车道 | 5GHz 的 36/149 等 |
| **频宽** | Bandwidth | 车道宽度（20/40/80/160MHz） | 160MHz 比 20MHz 快但更挤 |
| **空口** | Air Interface | 无线传输那段"空气" | 信号在空气中传的部分 |
| **Noise Floor** | 噪声底 | 背景噪声大小（dBm，越负越好） | -95 dBm 比 -85 dBm 干净 |
| **Channel Busy** | 信道忙时比 | 信道被占用的比例 | 70% 说明很挤 |
| **CCI** | Co-Channel Interference | 同信道干扰（邻居用同一信道） | 邻居也用 36 |
| **ACI** | Adjacent-Channel Interference | 邻信道干扰（邻居用隔壁信道） | 邻居用 40 挤到你 36 |
| **BSS** | Basic Service Set | 一个 WiFi 网络（邻居的路由器也算） | 扫到的"别人家的 WiFi" |
| **RSSI** | Received Signal Strength | 信号强度（dBm，越接近 0 越好） | -40 dBm 很强，-80 dBm 很弱 |
| **CCA** | Clear Channel Assessment | 发数据前先听信道空不空 | CCA 失败率高 = 信道太挤发不出去 |
| **重传率** | Retry Rate | 数据包发失败重发的比例 | 重传 20% 说明链路差 |
| **DFS** | Dynamic Frequency Selection | 动态频率选择（雷达频段避让） | 5G 部分信道与雷达共用，必须让 |
| **CAC** | Channel Availability Check | 切 DFS 信道前监听 60 秒确认无雷达 | 像"过马路前左右看" |
| **NOP** | Non-Occupancy Period | 检测到雷达后 30 分钟禁止再用 | 拉黑该信道 30 分钟 |
| **监管域** | Regulatory Domain | 各国频段法规（中国/美国/欧盟不同） | 中国 5G 信道和美国的可用的不一样 |
| **NSS** | Number of Spatial Streams | 空间流数（天线流数） | 4×4 MIMO = 4 流 |
| **MCS** | Modulation and Coding Scheme | 调制编码档位（速率等级） | MCS9 比 MCS0 快 |
| **hostapd** | Host AP daemon | 路由器上管理 WiFi 的守护进程 | ACS 从它拿信道数据 |
| **nl80211** | Netlink 802.11 | Linux 内核的无线配置接口 | 驱动和上层通信的管道 |
| **flow classify** | 流分类 | 识别流量是什么业务（DPI 的活） | 认出这是 Netflix 视频 |
| **CSV** | Comma-Separated Values | 逗号分隔的表格文件 | `时间戳,app_type,字节数,包数` |
| **BIZ** | Business Type | 业务类型（6 类） | IDLE/WEB/VIDEO/CALL/GAME/BULK |
| **时隙** | Slot | 一天切成 96 个 15 分钟窗口 | 20:15~20:30 是第 81 个时隙 |
| **EWMA** | Exponentially Weighted Moving Average | 指数加权平均（新旧数据按比例加权） | λ=0.85：新数据权重 15%，旧数据 85% |
| **JSD** | Jensen-Shannon Divergence | 两个概率分布差异度的度量 | 短期规律 vs 长期规律差多少 |
| **漂移** | Drift | 用户行为模式变了 | 用户从"白天用网"变成"晚上用网" |
| **HealthScore** | 健康分 | 当前信道的健康评分（0~100） | <65 算差，<20 强制切 |
| **DecisionScore** | 决策分 | 候选信道的决策评分（含切换代价） | 用于比较换不换 |
| **切换代价** | Switch Cost | 切换对业务的伤害 | 视频/通话/游戏时切换代价极大 |
| **安全窗口** | Safe Window | 适合切换的时机（无实时流+队列空+CPU闲） | 半夜没人用网时 |
| **驻留时间** | Min Hold Time | 在一个信道至少待多久 | 30 分钟 |
| **冷却** | Cooldown | 切完后多久不许再切 | 1 小时 |
| **连续获胜** | Consecutive Wins | 候选要连续领先 N 次才被信任 | 连续 3 次领先才切 |
| **降级切换** | Degraded Switch | 等不到安全窗口、降低标准硬切 | 5 分钟超时后 txq<50% 就切 |
| **CSA** | Channel Switch Announcement | 切换信道的通告帧（告诉客户端要换了） | 路由器广播"我要换车道了" |
| **TXQ** | Transmit Queue | 发送队列（待发送数据堆积量） | txq 高 = 网络正忙 |
| **env_profile_t** | Environment Profile | 环境识别结果结构体 | 记录"干扰严重度/主环境类型" |
| **channel_metrics_t** | Channel Metrics | 单个信道的指标结构体 | 忙时比/噪声/重传/RSSI 全在这 |
